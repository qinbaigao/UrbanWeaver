# UrbanWeaver 跨尺度协调留出集 v1

这套数据检验一个可证伪的问题。面对新的空间要求，在固定的工具、几何事实和尝试预算下，模型能否比固定顺序更准确或更经济地决定何时扩大修改范围？作者于 2026-11-21 在已有实现和先前实验之后构造并冻结了数据。未用任何参评方法在测试集上决定样本去留。它属于研究者侧、机制已知、场景和指令新编的留出集。其来源不具备第三方独立盲测的性质。

## 数据组成

| 用途 | 独立需求 | 起始场景 | 内容 |
|---|---:|---:|---|
| 开发 | 2 | 6 | 校门招领站、园艺备料室。仅用此部分联调三臂 |
| 受控测试 | 12 | 36 | 6 个地块—建筑任务族及 6 个楼层—房间任务族，每族一个相同需求配三个反事实起点 |
| 自然语言迁移测试 | 8 | 从零生成 | 18–40 栋城市，涉及跨街、跨河、跨层、使用功能与连续步行。独立报告 |

[开发输入](development/tasks.jsonl)和[受控测试输入](test/tasks.jsonl)每行含不透明 ID、中文指令、相对该任务清单的原生 city.json 路径和公开的测量/订货附件。全部场景为本次新建的米制局部街区，含一条道路、多个地块、目标楼及周边建筑。每次只交给被测方法当前一行和该行指向的场景。附件为三臂共同输入；受控组聚焦规划及作用域选择，不单独测自然语言解析能力。[迁移输入](transfer/tasks.jsonl)只含 ID 和指令。

每个受控族中，业务指令、订货尺寸和授权相同。变化只在初始空间条件，例如地块可用跨度、原建筑位置、相邻房间的余量或固定门位。三个条件分别允许局部完成、要求动用上层权限、以及在全部授权内无解。两种尺度每类各六例。测试任务打乱顺序，ID 不编码类别。不同任务不共享模型对话、记忆或工具轨迹。

- **地块—建筑。** 在指定地块满足营业面宽和进深。局部动作可以改变矩形楼壳尺寸、保持中心；跨层动作额外允许协调同一地块的沿街位置。楼门继续朝街，原街距、退界、邻楼与预留地受保护。预留地随附件以世界坐标矩形给出。此切片考察选址与楼壳的接口，不涉及改城市路网。
- **楼层—房间。** 在指定房间安装真实类别、原尺寸的设备组合。局部动作可平移组；跨层动作额外允许沿原方向移动与后勤室的共享隔墙。固定公共走廊、门洞、相邻净宽和门内通行带。设备清单的 u 轴沿临街方向的世界正轴，v 轴沿另一世界正轴，尺寸依次为 u、v 和高度。组的原点可平移；物体局部宽轴朝世界 +X 或 +Y，分别对应场景 yaw 0°、90°。物体 ID 为清单绑定名，共用输出适配器可以将等价的本地 ID 映射到它。此切片考察完整组合与楼层分区的取舍，不考察资产搜索、纹理或审美。
- **从零生成。** 例如，材料店与制作室需同时满足用地、陈设与避开未铺装绿地的步行连接。各任务独立编写，不预设模型必须反馈到哪一层。评分员查看[独立验收项](evaluation/transfer_rubric.jsonl)，参评方法只读文本。转移集尚无覆盖全部谓词的自动评分器，需在看结果前固定面积、座位匹配、路径、跨层连接和人工复核的共同判据。不得将这八条计入已有几何证书的 36 例。

## 冻结的受控比较协议

1. 从同一原生快照分别运行局部动作、固定顺序跨层、完整智能体跨层三臂。固定顺序和智能体使用相同的作用域、几何工具、动作参数范围、候选生成器、最终编译和保护条件。局部臂只关闭上层动作。三臂均读取同样的可测几何；所有数值约束仅从公开输入获得。禁止将 evaluation 目录、族名、类别、证明、参考位置或其他反事实实例送给参评方法。跨尺度由实际状态变化判定；涉及高层的对话或工具名本身不能证明上层进行了修改。
2. 先在开发集完成适配，记录三臂实现哈希后才执行测试。模型与固定排序的候选提案均从相同公共工具得到；工具应只给出查询所需的局部证据，禁止包装私有证书求解器作候选过滤。固定排序定义为先局部后上层、同层按动作改变量再按稳定 ID 排序。每例最多评估 6 个不同的成品候选，含首个；提前终止及重复提案都记录。模型决策回合上限 12，不设总 token 限额。各臂运行一次确定性选择或使用相同预定模型种子 51983，报告真实模型版本。若追加种子整批配对运行并单列。
3. 主要终点为全部 36 例的正确任务结果。24 个几何可行实例只接受通过成品评分的交付；12 个确证无解实例要求显式拒绝、有可从输入复核的理由、原场景保持原状。预算用尽、服务异常、无输出、无候选或无理由的保守拒绝单列为未完成。保护条件回归一律判交付失败。评阅拒绝理由时隐藏方法名。不得把拒绝全部任务计为高成功率。
4. 分开列三种条件下的交付、错误拒绝、错误接受，报告每臂首次和最终结果、实际尝试、向上调整次数、编译次数、模型调用、token 与墙钟。公布同例配对的胜/负/平，按 12 个需求族汇总差值及区间；三种反事实和重复种子不当作独立指令。相同成功数时只在配对案例上解释实际成本差异，同时保留全体成本。若固定规则持平或更好，照实报告。数据只覆盖两种空间接口，族内几何有意受控。
5. 版本清单见 [SHA256SUMS](SHA256SUMS)，参评前的源代码指纹和历史提示查重范围见 [冻结记录](evaluation/provenance.json)。如果测试后用这些题修改规划器，此 v1 随即成为开发数据；下一次确认性结论需要新留出集。已知答案的出题者应避免按测试条件为某一臂添加专用规则。条件允许时另做第三方出题或独立评分。

## 复核

在本目录执行 `sha256sum -c SHA256SUMS` 可离线核验冻结文件。在 CityG 根目录执行以下命令，使用 cityG 的 CPU 环境即可。

```bash
PYTHONPATH=src python benchmarks/cross_scale_holdout_v1/evaluation/audit.py > /tmp/uw_geometry_check.json
cmp /tmp/uw_geometry_check.json benchmarks/cross_scale_holdout_v1/evaluation/certificates.json
PYTHONPATH=src python benchmarks/cross_scale_holdout_v1/evaluation/score.py TASK_ID /path/to/final/city.json --split test
```

审核程序直接读实际初始快照和公开要求。选址题在满足最小尺寸的基础上，按地块边界和障碍边界分割连续可选中心区间；固定中心先检验。楼层题由组合的实际投影、不可动门洞、必要墙垛和后勤室最小宽度计算上界。可行样本还须构造一个实际成品，重新构建 CCWP，通过同一成品评分及几何编译。全部起点都必须原样未满足请求。证书用于审核题目，不能用作参评规划器。门区净空是显式二维几何约束，不表示已经运行全程动力学。

局部臂评分时给 score.py 添加 `--local-only`，以最终几何强制核对中心或隔墙保持原位。受控成品评分器校验作用域、房间/街道接口、原尺寸设备相对位置、保留的门和实际编译的设备。拒绝、成本及来源记录由比较运行器另外采集。生成开发/受控输入可运行 `PYTHONPATH=src python benchmarks/cross_scale_holdout_v1/evaluation/build.py 新目录`，为防止改写冻结数据，目标必须不存在。
