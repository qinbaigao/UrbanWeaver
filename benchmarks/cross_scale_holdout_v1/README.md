# UrbanWeaver cross-scale coordination holdout v1

This benchmark asks when a planner should expand the scope of an edit. With the same tools, measurable geometry and attempt budget, does an agent choose that scope more accurately or at lower cost than a fixed search order?

The authors froze these newly written instructions and scenes on 2026-11-21, after developing the mechanisms and running earlier experiments. Test outcomes from the compared methods played no part in case selection. This is an author-designed holdout with known mechanisms. The original Chinese protocol is preserved byte-for-byte for verification. [Frozen protocol (Chinese)](protocol.zh-CN.md)

## Splits and inputs

| Split | Distinct briefs | Starting scenes | Contents |
|---|---:|---:|---|
| Development | 2 | 6 | A school lost-property office and a gardening preparation room, used to integrate the three comparison arms |
| Controlled test | 12 | 36 | Six parcel–building families and six floor–room families, each with three counterfactual starting scenes |
| Language transfer | 8 | Generated from scratch | Cities with 18–40 buildings and requirements involving street, river and floor crossings, functional uses and continuous walking routes |

Each development or controlled-test row contains an opaque ID, a Chinese instruction, a relative path to a native `city.json`, and shared measurement or order details. Each scene is a new metric street segment with parcels, a target building and neighbours. Give a method only the current row and its referenced scene. The controlled comparison measures planning and scope choice with shared attachments. Transfer rows contain just an ID and instruction. [Development](development/tasks.jsonl) · [Controlled test](test/tasks.jsonl) · [Transfer](transfer/tasks.jsonl)

Within a controlled family, the brief, ordered dimensions and authorized changes stay fixed. Only the starting spatial conditions vary, such as available frontage, the original building centre, spare room width or a fixed door. One start admits a local solution, one needs an upper-level action, and one is infeasible within the authorized scope. Each scale has six cases of each kind. The test order is shuffled and IDs conceal the condition. Reset conversations, memory and tool traces between cases.

- **Parcel–building.** Fit the requested frontage and depth inside the specified parcel. A local action resizes the rectangular shell around its original centre. An upper-level action may also move the shell along the street within the parcel. Preserve the street-facing entrance, original street offset, setbacks, neighbours and reserved areas. The attachment gives reserved rectangles in world coordinates. The road network stays fixed.
- **Floor–room.** Install the specified equipment group at full size. A local action translates the group. An upper-level action may also shift the shared partition with the service room while preserving its orientation. Protect the public corridor, door openings, neighbouring clear width and entrance passage. The order lists dimensions as u, v and height. The u-axis follows the positive world axis parallel to the street and v follows the other positive axis. The group origin may translate. An object's width axis points along world +X or +Y (scene yaw 0° or 90°). Order IDs bind individual items; the shared output adapter can map equivalent local IDs. Asset retrieval, texturing and aesthetics are outside the score.
- **Language transfer.** For example, a materials shop and a workshop may need suitable sites, furnishings and a walking connection that avoids unpaved greenery. These independently written briefs leave the escalation level open. Methods receive only the brief. Evaluators use a separate rubric. Before inspecting results, fix common criteria for area, seating, paths, floor connections and human review. The automatic scorer covers only some transfer predicates. Report these eight tasks separately from the 36 certified controlled cases. [Transfer rubric](evaluation/transfer_rubric.jsonl)

## Controlled comparison protocol

1. Run three arms from each identical snapshot: local actions only, fixed-order cross-scale search, and agent-guided cross-scale search. The last two share scopes, geometry tools, parameter ranges, candidate generators, final compilation and protection checks. The local arm disables upper-level actions. All three see the same measurable geometry and derive numeric constraints only from the public input. Keep evaluation files, family names, condition labels, proofs, reference placements and sibling counterfactuals hidden from the methods. Credit escalation only for an actual upper-level state change.
2. Integrate on development data and record implementation hashes before testing. Both cross-scale arms obtain candidates from the same public tools. Tools return evidence local to the query; private certificate solvers must stay outside candidate filtering. Fixed order tries local actions first, then upper-level actions, sorting within each scope by magnitude of change and stable ID. Evaluate at most six distinct finished candidates per case, including the first. Record early termination and duplicate proposals. Allow up to 12 model decision rounds with no cumulative token cap. Run each arm deterministically or with the predeclared model seed 51983 and record the actual model version. Report any additional seeds as separate, fully paired runs.
3. Score the final task outcome on all 36 cases. For the 24 feasible starts, the delivered city must pass the output scorer. For the 12 certified infeasible starts, require an explicit refusal with a reason independently checkable from the input and an unchanged source scene. Record budget exhaustion, service failure, missing output, empty candidate sets and unsupported refusals as incomplete. Any regression in a protected condition fails delivery. Blind reviewers to method names when judging refusal reasons.
4. For each starting condition, report delivery, false refusals and false acceptances. For each arm, report first and final outcomes, attempts, escalations, compilations, model calls, tokens and wall time. Publish paired wins, losses and ties and summarize differences and intervals over the 12 brief families. Counterfactual starts and repeated seeds share a brief. When success counts are equal, use matched cases to interpret cost differences and retain the aggregate costs. Report ties or advantages for fixed order as observed. The controlled geometry covers two scale interfaces.
5. The manifest records the frozen file digests; its protocol entry now points to the original Chinese text. Provenance records the pre-evaluation code fingerprints and checks for overlap with historical prompts. If results inform planner changes, treat v1 as development data for that version and use a fresh holdout for confirmation. Avoid condition-specific rules informed by known answers. Independently authored tasks or independent scoring provide additional checks. [File manifest](SHA256SUMS) · [Provenance](evaluation/provenance.json)

## Verify and score

Run `sha256sum -c SHA256SUMS` in this directory to verify the frozen files offline. From the repository root, use the CPU environment to reconstruct and compare the certificates, then score a finished city:

```bash
PYTHONPATH=src python benchmarks/cross_scale_holdout_v1/evaluation/audit.py > /tmp/uw_geometry_check.json
cmp /tmp/uw_geometry_check.json benchmarks/cross_scale_holdout_v1/evaluation/certificates.json
PYTHONPATH=src python benchmarks/cross_scale_holdout_v1/evaluation/score.py TASK_ID /path/to/final/city.json --split test
```

The audit reads the original snapshots and public requirements. For siting, it tests the fixed centre first and divides the continuous range of possible centres using parcel and obstacle boundaries at the minimum admissible dimensions. For floors, the equipment footprint, fixed openings, required wall piers and minimum service-room width bound the available space. Each feasible case also requires a constructed output that passes CCWP reconstruction, output scoring and geometry compilation. Every initial snapshot must fail its request. Certificates audit the instances and must stay outside the evaluated planner. Door clearance is an explicit 2D geometric check.

For the local arm, pass `--local-only` to `score.py` to verify from final geometry that the centre or partition stayed fixed. The scorer checks scope, room or street interfaces, relative equipment placement at original size, protected doors and compiled equipment. The comparison runner separately records refusals, costs and provenance. To regenerate the development and controlled inputs, run `PYTHONPATH=src python benchmarks/cross_scale_holdout_v1/evaluation/build.py NEW_DIRECTORY` with a destination that does not yet exist.
